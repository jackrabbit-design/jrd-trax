# Secret Management & Release Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get the Kantata OAuth client secret out of committed source and into a manual GitHub Actions pipeline that builds and publishes an ad-hoc `.app` release for the team.

**Architecture:** A gitignored `Secrets.swift` (with a committed `.example` template) supplies the secret to the same `TraxApp` SwiftPM target used by both `swift build`/`swift test` and the Xcode project. `project.yml` gains an explicit shared scheme so a clean checkout can be built headlessly. A `workflow_dispatch`-triggered GitHub Actions workflow writes `Secrets.swift` from a repo secret, archives via `xcodebuild` with code signing disabled, and publishes the zipped `.app` as a GitHub Release.

**Tech Stack:** Swift 6 / SwiftPM, XcodeGen, Xcode command-line tools, GitHub Actions (macos-latest runner), GitHub CLI (`gh`) for release creation.

**Spec:** docs/superpowers/specs/2026-09-17-release-pipeline-design.md

## Global Constraints

- The real `client_secret` must never be written into any file tracked by git (spec: "Secret handling").
- `Secrets.swift` is consumed identically by `swift build`/`swift test` and `Trax.xcodeproj` — no per-build-system special-casing (spec: "Secret handling").
- The release workflow triggers only on `workflow_dispatch` — no automatic builds on push (spec: "CI / release pipeline").
- Code signing is ad-hoc/disabled for this pipeline — no Developer ID, no notarization (spec: "Out of scope").
- `xcodegen generate` must be re-runnable locally without changing anyone's existing local workflow (spec: "Scheme fix").

### Task 2: Add a shared Xcode scheme via `project.yml`

**Files:**
- Modify: `project.yml`

**Interfaces:**
- Consumes: the `Trax` target already defined in `project.yml` (this task only adds a `schemes:` block referencing it).
- Produces: a shared scheme named `Trax`, regenerated by `xcodegen generate`, buildable/archivable via `xcodebuild -project Trax.xcodeproj -scheme Trax` (Task 3 depends on this scheme existing).

- [ ] **Step 1: Add the `schemes:` block**

Edit `project.yml` to add a `schemes:` top-level key (as a sibling of `targets:`), defining a shared scheme for the `Trax` target with build and archive actions:

```yaml
schemes:
  Trax:
    build:
      targets:
        Trax: all
    archive:
      config: Release
```

The full file should read:

```yaml
name: Trax
options:
  bundleIdPrefix: com.jackrabbit
  deploymentTarget:
    macOS: "14.0"
packages:
  TraxAppPackage:
    path: .
targets:
  Trax:
    type: application
    platform: macOS
    sources:
      - path: XcodeApp/Trax
    dependencies:
      - package: TraxAppPackage
        product: TraxApp
    settings:
      base:
        PRODUCT_BUNDLE_IDENTIFIER: com.jackrabbit.trax
        PRODUCT_NAME: Trax
        GENERATE_INFOPLIST_FILE: YES
        ENABLE_HARDENED_RUNTIME: YES
schemes:
  Trax:
    build:
      targets:
        Trax: all
    archive:
      config: Release
```

### Task 3: Add the manual GitHub Actions release workflow

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `Secrets` type from Task 1 (writes `TraxApp/Sources/TraxApp/Secrets.swift` at the same path), the `Trax` scheme from Task 2.
- Produces: a GitHub Release with a `Trax.zip` asset, triggered manually.

- [ ] **Step 1: Create the workflow file**

Create `.github/workflows/release.yml`:

```yaml
name: Release build

on:
  workflow_dispatch:
    inputs:
      tag:
        description: "Release tag (e.g. v0.3.0). Leave blank to use the run number."
        required: false
        type: string

jobs:
  build:
    runs-on: macos-latest
    permissions:
      contents: write
    env:
      DEVELOPER_DIR: /Applications/Xcode.app/Contents/Developer
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Write Secrets.swift
        run: |
          cat > TraxApp/Sources/TraxApp/Secrets.swift <<EOF
          enum Secrets {
              static let kantataClientSecret = "${{ secrets.KANTATA_CLIENT_SECRET }}"
          }
          EOF

      - name: Install XcodeGen
        run: brew install xcodegen

      - name: Generate Xcode project
        run: xcodegen generate

      - name: Archive
        run: |
          xcodebuild archive \
            -project Trax.xcodeproj \
            -scheme Trax \
            -configuration Release \
            -archivePath build/Trax.xcarchive \
            CODE_SIGN_IDENTITY="" \
            CODE_SIGNING_REQUIRED=NO \
            CODE_SIGNING_ALLOWED=NO

      - name: Zip the app
        run: |
          cd build/Trax.xcarchive/Products/Applications
          zip -r ../../../../Trax.zip Trax.app

      - name: Determine tag
        id: tag
        run: |
          if [ -n "${{ inputs.tag }}" ]; then
            echo "value=${{ inputs.tag }}" >> "$GITHUB_OUTPUT"
          else
            echo "value=build-${{ github.run_number }}" >> "$GITHUB_OUTPUT"
          fi

      - name: Publish release
        uses: softprops/action-gh-release@v2
        with:
          tag_name: ${{ steps.tag.outputs.value }}
          name: Trax ${{ steps.tag.outputs.value }}
          body: |
            Unsigned build for internal team use.

            On first launch, macOS will show an "unidentified developer" warning.
            Right-click (or Control-click) `Trax.app` and choose **Open** to bypass it.
          files: Trax.zip
```

- [ ] **Step 2: Add the repository secret (manual, one-time, done by you in the GitHub UI)**

In the GitHub repo (`jackrabbit-design/jrd-trax`) → Settings → Secrets and variables → Actions → New repository secret:
- Name: `KANTATA_CLIENT_SECRET`
- Value: your real Kantata client secret

This step has no shell command — it's done directly in the GitHub web UI, not via `gh` or committed config, since the value must never touch a shell history or a file.

- [ ] **Step 3: Validate the workflow YAML locally**

```bash
python3 -c "import yaml, sys; yaml.safe_load(open('.github/workflows/release.yml'))" && echo "valid YAML"
```

Expected: `valid YAML` with no errors.

- [ ] **Step 4: Commit**

```bash
git add .github/workflows/release.yml
git commit -m "Add manual release workflow that builds and publishes an ad-hoc Trax.app"
```

- [ ] **Step 5: Manually trigger the workflow after this plan is merged**

This can only be done once the branch is merged and the `KANTATA_CLIENT_SECRET` repo secret exists (Step 2). From the GitHub repo's Actions tab, select "Release build" → "Run workflow". Confirm a Release is published with a working `Trax.zip` attached, and that unzipping and right-click-opening `Trax.app` launches the sign-in flow successfully. This is a manual, one-time post-merge verification — not part of the automated task loop.
